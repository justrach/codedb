196:## 3. Codesign each binary (hardened runtime)
197-
198-Notarization **requires** the hardened runtime (`--options runtime`) and a secure
199-timestamp (`--timestamp`). Sign every binary you intend to ship.
200-
201-### 3.1 Sign
202-
203-Per-target binaries:
204-
205-```bash
206-for bin in \
207-  "$AARCH64_DIR/graff" "$AARCH64_DIR/codegraff" \
208-  "$X86_64_DIR/graff"  "$X86_64_DIR/codegraff"
209-do
210-  codesign --force --timestamp --options runtime \
211-    --sign "Developer ID Application: Rachit Pradhan (WWP9DLJ27P)" \
212-    "$bin"
213-done
214-```
215-
216-(If you built universal binaries in 2.3, sign
217-`target/universal-apple-darwin/release/{graff,codegraff}` the same way.)
218-
219-Flags explained:
220-
221-- `--force` — replace any existing signature (release artifacts are sometimes
222-  ad-hoc signed by the linker).
223-- `--timestamp` — embed a trusted Apple timestamp (mandatory for notarization).
224-- `--options runtime` — enable the **hardened runtime** (mandatory for
225-  notarization).
226-- `--sign "<identity>"` — the Developer ID Application identity from step 1.2.
227-
228-### 3.2 Verify the signature
229-
230-```bash
231-for bin in \
232-  "$AARCH64_DIR/graff" "$AARCH64_DIR/codegraff" \
233-  "$X86_64_DIR/graff"  "$X86_64_DIR/codegraff"
234-do
235-  echo "=== $bin ==="
236-  codesign -dvvv --verbose=4 "$bin"
237-done
238-```
239-
240-In the output for each binary, confirm:
241-
242-- `Authority=Developer ID Application: Rachit Pradhan (WWP9DLJ27P)`
243-- `Authority=Developer ID Certification Authority`
244-- `Authority=Apple Root CA`
245-- `Timestamp=...` (a real date, not "none")
246-- `flags=0x10000(runtime)` — confirms the hardened runtime is on.
247-
248-A quick structural check should also pass:
249-
250-```bash
251-codesign --verify --strict --verbose=2 "$AARCH64_DIR/graff"
252-```
253-

256:## 4. Notarize
257-
258-Apple's notary service only accepts archives (`.zip`, `.dmg`, `.pkg`), not bare
259-executables. Zip the signed binaries, then submit and wait.
260-
261-### 4.1 Zip the signed binaries
262-
263-Use `ditto` so macOS metadata and the embedded signature are preserved exactly:
264-
265-```bash
266-ditto -c -k --keepParent "$AARCH64_DIR/graff"     graff-aarch64.zip
267-ditto -c -k --keepParent "$AARCH64_DIR/codegraff" codegraff-aarch64.zip
268-ditto -c -k --keepParent "$X86_64_DIR/graff"      graff-x86_64.zip
269-ditto -c -k --keepParent "$X86_64_DIR/codegraff"  codegraff-x86_64.zip
270-```
271-
272-`zip` also works if you prefer it (`zip graff-aarch64.zip "$AARCH64_DIR/graff"`),
273-but `ditto -c -k --keepParent` is the recommended, metadata-safe form.
274-
275-### 4.2 Submit and wait
276-
277-Submit each archive **sequentially** (see pitfall 6.4 — do not background these
278-in parallel). `--wait` blocks until Apple returns a terminal status.
279-
280-```bash
281-for z in graff-aarch64.zip codegraff-aarch64.zip graff-x86_64.zip codegraff-x86_64.zip; do
282-  echo "=== submitting $z ==="
283:  xcrun notarytool submit "$z" \
284-    --keychain-profile codedb-notary \
285-    --wait
286-done
287-```
288-
289-Read the status block at the end of each submission. A success looks like:
290-
291-```
292-  status: Accepted
293-```
294-
295-Anything else (`Invalid`, `Rejected`) means notarization failed for that
296-archive — fetch the log (next step).
297-
298-### 4.3 Fetch the log on failure
299-
300-Every submission prints an `id:` (the submission UUID). To see exactly what Apple
301-flagged:
302-
303-```bash
304-xcrun notarytool log <submission-id> --keychain-profile codedb-notary
305-```
306-
307-The JSON `issues[]` array lists each problem. The most common causes are a
308-missing hardened runtime (`--options runtime` was omitted in step 3) or a missing
309-secure timestamp (`--timestamp` was omitted). Fix, re-sign (step 3), re-zip
310-(4.1), and re-submit.
311-
312-You can also list recent submissions to recover an ID you missed:
313-
314-```bash
315-xcrun notarytool history --keychain-profile codedb-notary
316-```
317-

320:## 5. Staple & verify
321-
322-### 5.1 Stapling does not apply to bare CLI executables
323-
324-`xcrun stapler staple` attaches the notarization ticket to a **container** —
325-a `.app` bundle, `.dmg`, or `.pkg`. **You cannot staple a bare Mach-O
326-executable** like `graff` or `codegraff`; `stapler` will report that the format
327-is unsupported.
328-
329-This is fine. For a bare CLI binary, Gatekeeper validates the notarization ticket
330-**online** the first time the binary runs (the ticket is published on Apple's
331-servers, keyed by the binary's code-signature hash). As long as the machine has
332-network access on first launch, the online check confirms notarization. Stapling
333-only matters when you wrap the binaries in a `.dmg`/`.pkg`/`.app` — in that case,
334-staple the container:
335-
336-```bash
337-# Only if you ship a .dmg / .pkg / .app:
338-xcrun stapler staple codegraff-installer.dmg
339-xcrun stapler validate codegraff-installer.dmg
340-```
341-
342-### 5.2 Verify the bare binaries
343-
344-Confirm the signature is intact and strict:
345-
346-```bash
347-codesign --verify --strict --verbose=2 "$AARCH64_DIR/graff"
348-codesign --verify --strict --verbose=2 "$AARCH64_DIR/codegraff"
349-codesign --verify --strict --verbose=2 "$X86_64_DIR/graff"
350-codesign --verify --strict --verbose=2 "$X86_64_DIR/codegraff"
351-```
352-
353-Run a Gatekeeper assessment. Since these are standalone executables (not bundled
354-installers), assess them as installable items:
355-
356-```bash
357-spctl -a -vvv -t install "$AARCH64_DIR/graff"
358-spctl -a -vvv -t install "$AARCH64_DIR/codegraff"
359-```
360-
361-A notarized, correctly signed binary reports:
362-
363-```
364-source=Notarized Developer ID
365-```
366-
367-### 5.3 Gatekeeper behavior for downloaded binaries
368-
369-When a user downloads one of these binaries via a browser or `curl`-from-a-page,
370-macOS attaches a **quarantine** xattr (`com.apple.quarantine`). On first
371-execution Gatekeeper performs an online notarization check; because the binaries
372-are notarized, they are allowed to run without the "unidentified developer"
373-block. If the binary were signed but **not** notarized, Gatekeeper would block
374-it. This is exactly why notarization (section 4) is mandatory even though we
375-cannot staple a bare CLI binary.

379-## 6. Common pitfalls
380-
381-### 6.1 `com.apple.provenance` / quarantine xattr — clear it on the destination
382-
383-macOS adds extended attributes (`com.apple.quarantine` on download,
384-`com.apple.provenance` on execution-launch tracking). These can interfere with
385-signature verification and launch behavior. On the **destination** machine/path,
386-strip them from the installed binary:
387-
388-```bash
389-xattr -c /usr/local/bin/graff
390-xattr -c /usr/local/bin/codegraff
391-```
392-
393-Inspect what is attached first if you want to confirm:
394-
395-```bash
396-xattr -l /usr/local/bin/graff
397-```
398-
399-### 6.2 Re-sign after any copy — `cp` can break the signature
400-
401-This matches the project's known **"graff/codegraff need re-signing after every
402-build or `Killed: 9`"** failure mode. Copying, moving, regenerating, or otherwise
403-touching a signed binary can invalidate the code signature, and macOS will kill
404-an invalidly-signed hardened-runtime binary on launch with `Killed: 9`.
405-
406-After **any** `cp`/`install`/`lipo`/rebuild that produces or relocates the final
407-artifact, re-run the codesign step (section 3) on the final file, then verify:
408-
409-```bash
410-cp "$AARCH64_DIR/graff" /usr/local/bin/graff
411-codesign --force --timestamp --options runtime \
412-  --sign "Developer ID Application: Rachit Pradhan (WWP9DLJ27P)" \
413-  /usr/local/bin/graff
414-codesign --verify --strict --verbose=2 /usr/local/bin/graff
415-```
416-
417-Always sign the file **at its final location**, or re-sign after moving it.
418-
419-### 6.3 Use `xattr -c`, not `xattr -cr`
420-
421-Use `xattr -c` (clear attributes on the file) — **not** `xattr -cr`. The
422-recursive form `-cr` walks directories and is the wrong tool for individual
423-binaries; it can also strip attributes from things you did not intend to touch.
424-For a single executable, `xattr -c <bin>` is correct.
425-
426-### 6.4 Submit notarizations sequentially, not in parallel
427-
428:Run `notarytool submit ... --wait` calls **one at a time**. Do not background
429-multiple submissions or fan them out in parallel — concurrent uploads against the
430-notary service are unreliable and can stall or error. The loop in step 4.2 is
431-intentionally sequential; keep it that way.
432-
433-### 6.5 Sign last
434-
435-Every operation that rewrites the file bytes — `strip`, `lipo -create`, `cp`,
436-rebuild — invalidates the signature. Codesigning must be the **final** step
437-before zipping for notarization, and must be re-applied after any later copy
438-(see 6.2).
