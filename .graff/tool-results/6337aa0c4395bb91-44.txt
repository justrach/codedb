   43 | /// The real entry point. In Debug builds, Zig may merge all command-branch
   44 | /// stack frames into one producing a frame that overflows the default OS stack,
   45 | /// so those builds trampoline through a thread with an explicit 64 MB stack.
   46 | /// Optimized builds have a ~190 KB frame and run directly on the process stack,
   47 | /// avoiding an OS thread create/join on every CLI invocation.
   48 | ///

   50 | /// `pub fn main(...) !void` ad-hoc-signed and run via Rosetta (or, in the
   51 | /// user-reported case, on a native macOS Intel build that ends up with a
   52 | /// similar startup-path tripwire) segfaults BEFORE main runs — the runtime's
   53 | /// error-handling wrapper is what crashes. Verified with a minimal repro:
   54 | /// `pub fn main(init) void { ... }` works; `!void` does not. Same crash
   55 | /// happens if the entry point spawns a thread before writing to stderr.

   57 | /// fallible work into mainImpl which runs after we've already had a chance
