**High — inconsistent index pair can be published:** `src/index.zig:1862` renames the new postings file before the lookup file is written/renamed at `:1894`. A crash or concurrent writer can leave a new postings file paired with an old lookup; matching format headers make this loadable, yielding wrong candidates rather than a clean rebuild. Fix: write generation-suffixed postings/lookup files, fsync both, then atomically publish a small manifest naming that generation (and have loaders validate/read it). Tradeoff: one tiny metadata read/write and stale-generation cleanup.
