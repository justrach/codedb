## report

## P1 — Benchmark regression gate cannot compare against the Zig 0.16 base

**`.github/workflows/bench-regression.yml:44-52`** installs only Zig 0.17, then runs the base branch benchmark with that compiler. The target baseline uses Zig 0.16, so its build can fail solely from compiler incompatibility; the workflow then sets `have_base_json=false` and publishes a successful “Skipped strict comparison” report. Retrieval/performance regressions can therefore merge despite the release claiming validated Zig 0.16 A/B parity.

**Fix:** install each revision’s declared Zig version in its worktree, or use a checked-in immutable 0.16 benchmark artifact. Once the base supports benchmark JSON, make base failure fatal rather than silently bootstrapping.

## P1 — The persisted trigram index is not atomically published as a pair

**`src/index.zig:1928-1929`** renames `trigram.postings` and `trigram.lookup` independently. A reader—or interruption—between those operations observes lookup/postings from different generations. This can reject a valid cache or produce retrieval against mismatched offsets if validation does not catch every compatible-looking combination.

**Fix:** generation-stamp both files and atomically rename a manifest selecting the completed generation, or publish a generation directory with one atomic pointer/directory swap. Add a fault/concurrent-reader test between the two publication operations. The comment at **`src/index.zig:1728`** and release language should not call the two-file index atomic until then.

## P2 — Release verification overstates parity coverage

**`CHANGELOG.md:67-69, 82-87`** claims parity across sequential/parallel indexing, persisted/mmap round-trips, lazy rebuilding, and immutable-corpus hit counts. The staged automated tests cover selected fixtures, but there is no checked-in gate reproducing the cited immutable-corpus Zig 0.16-vs-0.17 comparison, and the CI A/B path is ineffective as described above. The lazy rebuild test at **`src/test_explore.zig:373-420`** compares the initial result as an unordered set, so it does not establish 1:1 ordered-output parity.

**Fix:** add a deterministic cross-version corpus parity job comparing complete ordered outputs, paths, lines, masks, and caps; make the lazy rebuild test compare ordered results unless ordering is explicitly outside the API contract. Otherwise narrow the release claims to the fixtures actually exercised.

## Verdict

**BLOCK** — two P1 merge blockers: the regression gate can silently skip the relevant baseline, and two-file persistence lacks generation-atomic publication. `zig build test` passes, but it does not cover either blocker.
