## Merge-blocking

- **High — `WordIndex.searchDeduped` no longer fulfills its contract or preserves malformed-index behavior.**  
  **`src/index.zig:525-530`** now blindly copies `search()` results, despite the function’s documented guarantee to deduplicate `(doc_id, line_num)`. Normal indexing currently suppresses adjacent duplicates, but mmap/disk input is not established here as validated unique, and callers can observe malformed or legacy postings. The new test at **`src/test_index.zig:559-565`** merely asserts equality with raw postings, effectively testing away the contract rather than testing deduplication.  
  **Fix:** retain deduplication, or first validate/prove uniqueness when loading/building every posting source and rename the API. A low-overhead compromise is a linear adjacent-duplicate pass only if ordering/contiguity is guaranteed; otherwise retain the hash fallback for ordering breaks. Add a test containing duplicate and non-adjacent duplicate `(doc_id, line_num)` entries.

## Lesser risks

- **Medium — the Tier-0 fast path relies on an invariant not enforced at its boundary.**  
  **`src/explore.zig:3508-3520`** treats any nondecreasing `doc_id` sequence as grouped. This is mathematically sufficient for one contiguous run per ID, and the fallback correctly handles ordering breaks, but malformed postings with duplicate lines remain counted and emitted differently now that `searchDeduped` stopped sanitizing them. Fixing `searchDeduped`, or validating persisted postings, resolves this coupling. The ordering scan itself is real but adds a full pass; benchmark short/common terms to ensure avoiding the table outweighs that scan.

- **Low — release direct execution rests on an unverified platform stack-size assumption.**  
  **`src/main.zig:55-60`** bypasses the explicit stack for every non-Debug mode. A measured ~190 KB frame is likely safe on mainstream process stacks, but this should be checked for Windows release binaries and cross-compiled architectures, where linker/default stack reservations differ. Consider retaining a trampoline only for targets with insufficient guaranteed process stack, or set the Windows stack reserve explicitly in the build.

- **Low — Windows borrowed argv intentionally leaks bootstrap allocations.**  
  **`src/cio.zig:482-489`**, consumed at **`src/main.zig:48-50`**, converts Windows arguments into process-lifetime storage without an ownership handle, so neither the converted slice nor pointer array can be released. This is bounded to startup and keeps pointers valid across the Debug worker, but document it explicitly as process-lifetime ownership; otherwise return an owned wrapper with a deinitializer.

- **Tests:** `zig build test --summary all` passed, but results were cached. No focused malformed-posting or exact-output-equivalence test covers the principal regression.
