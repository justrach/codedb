# codedb 0.2.5826

_Released 2026-06-23._

A **correctness + coverage + agent-steering** release. The headline is index
coverage: medium files (512 KB – 2 MB) that the previous release silently
dropped are now fully indexed and searchable, verified by a controlled A/B run
across 10 isolated sandboxes. Alongside that, editor MCP launches that pass an
unexpanded `${workspaceFolder}` now resolve correctly, `index` is a first-class
command, and a batch of agent-steering and correctness fixes land — on top of a
`main.zig` split into focused modules and a halved live-update read path.

---

## Headline: index coverage widened to 2 MB (#635)

`max_indexed_file_bytes` moved **512 KB → 2 MB**. Before this, any file between
512 KB and 2 MB — generated code, vendored bundles, lockfiles, data fixtures —
was dropped from the index entirely. It was invisible to `search`, `word`,
`symbol`, and `find`, and reachable only via a direct `codedb_read`. There was no
error; the file simply did not exist as far as retrieval was concerned.

Now those files are indexed: **full trigram up to 1 MB, outline + word index up
to 2 MB.** Files larger than 2 MB are still skipped, but the skip is logged
instead of silent.

### Empirical verification

We validated the fix with a controlled A/B, not an assertion. In 10 separate
microVM sandboxes, each binary (`0.2.5825` and `0.2.5826`) indexed an **identical
fixture repo** — files at eight sizes (50 KB … 1.9 MB), each carrying a unique
sentinel token — in its **own root path** so the two never shared a snapshot.
Each binary was then asked to `search` for every sentinel.

| file size        | 0.2.5825 (previous) | 0.2.5826 (this release) |
|------------------|---------------------|-------------------------|
| 50 KB            | found 10/10         | found 10/10             |
| 400 KB           | found 10/10         | found 10/10             |
| 550 KB           | **0/10**            | **10/10**               |
| 700 KB           | **0/10**            | **10/10**               |
| 900 KB           | **0/10**            | **10/10**               |
| 1100 KB          | **0/10**            | **10/10**               |
| 1500 KB          | **0/10**            | **10/10**               |
| 1900 KB          | **0/10**            | **10/10**               |

Deterministic, zero variance across all 10 replicates. Every medium file the
previous release made unsearchable is found every time by this one. The fix
reaches the **cold CLI scan**, not just the live watcher path.

> Methodology note: a naive A/B that points both binaries at the *same* root path
> reports a false "no difference" — codedb's project cache is keyed by the root
> path, so whichever binary indexes first builds the snapshot and the second just
> loads it. Isolate by path (or clear the cache) when benchmarking two builds.

## Editor `${workspaceFolder}` MCP launches (#639)

Editors such as Zed and opencode launch `codedb mcp ${workspaceFolder}`. When the
client does not expand the variable, the literal string `${workspaceFolder}`
arrived as an **explicit** root and pinned the index to a directory of that name.
That single misclassification disabled three recovery paths at once — the #502
git-root walk-up, the deferred-scan handshake, and the `CODEDB_ROOT` fallback —
leaving the user with an empty index and no error.

The unexpanded placeholder now normalizes to **cwd, non-explicit**, so all three
paths fire as they would for a bare `codedb mcp`. The root-resolution gates were
extracted into pure, unit-tested predicates (`mcpRootIsImplicitCwd`,
`mcpRootAcceptsEnv`) so the *parse* and *consume* halves can no longer drift —
which is the exact gap that let this bug hide.

## Other fixes

- **`index` is a first-class command (#633)** — `codedb index` /
  `codedb <root> index` are now explicitly recognized rather than falling through
  to the default path.
- **`codedb_read` raw mode is byte-exact (#632)** — ranged reads in `mode=raw`
  no longer carry line-number decoration.
- **Absolute in-project paths accepted (#629)** — `codedb_read`/`codedb_edit` no
  longer reject an absolute path that points *inside* the indexed root.
- **Regex alternation scans all branches (#628)** — `a|b` where one branch has no
  trigram no longer silently drops the other branch's matches.
- **In-tree `codedb.snapshot` hidden from git (#625)** — appended to
  `.git/info/exclude`, so the index never pollutes `git status`.
- **Agents steered to structural tools (#626)** — `symbol`/`callers`/`deps`/
  `outline` are framed as the path of least resistance; `search` as fallback.
- **Convergence governor (#624)** — repeated identical nav calls get an in-band
  nudge to change strategy, capping token runaways on large repos.

## Performance

- **Live-update reads each changed file once.** The watcher used to hash a
  changed file (one full read) and then index it (a second), up to two reads of
  every edit. `hashAndIndexFile` now reads once and reuses the buffer for both,
  roughly halving file I/O per save while `codedb mcp` runs.

## Internal

- **`main.zig` split into focused modules** — the 2345-line `main.zig` became
  `background`, `bootstrap`, `cli_args`, `cli_proxy`, `commands`, `out`, `query`
  (≤ 600 lines each). Behaviour-preserving, and the enabling step for the
  predicate extractions above.
- **`isHelpRequest` predicate** — `--help`/`-h`/`help` was hand-written at four
  sites; it now lives in one place with a reintroduction guard.

## Upgrade notes

Drop-in. No config, flag, or on-disk format changes. The first `codedb mcp` or
`codedb <root> search` after upgrading re-scans and will now pick up any medium
(512 KB – 2 MB) files that were previously missing from the index.

## Verification

- **Full test suite:** 859/859 across all 23 binaries.
- **Release binary smoke test:** the shipped `codedb-linux-x86_64` was exercised
  in a sandbox microVM — version, cold index, `search`/`word`/`find`, `mcp --help`
  combos, and the 2 MB indexing path — see the release log.
- **Notarization:** macOS binaries signed with Developer ID and notarized via
  Apple's notary service (`notary-local`).
