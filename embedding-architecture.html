K3’s trick, 5M active.

Not a 5M dense model and not a static bag-of-words table. Distill a ~100M MoE code embedder that only fires ~5M params per token — 64–128 experts, top-2. Serve it on a cloud GPU with ZDR. Bootstrap (task, chunk) KV pairs from the codedb harness + codegraff, label in parallel streams. Kimi-K3 only grades pairs offline. Judge is still fewer codedb calls on OpenClaw and React.

K3 · 896 experts · teacher student · ~100M stored · ~5M active ZDR cloud GPU · parallel streams harness + graff → KV pairs static mean cannot unweight “gateway bind”

Why bother

Lexical miss

“gateway bind” beats net.ts. “flush passive effects” lands on a call site, not flushPassiveEffects at L4691. Knobs already took dual-repo calls 28 → 25. The rest is intent, not tokens.

Keep rule

Train on OpenClaw + React + codedb. Hold one repo out. Keep the vec only if graff+luna call count drops on both suites and score does not fall. Cheap MRR up + calls up = discard.
